# آزمون بار و جابه‌جایی OTP

ابزار `scripts/otp-load-test.ts` فقط روی SQL Server محلی اجرا می‌شود. شماره‌ها، درخواست‌های تأیید و حساب‌ها مصنوعی‌اند؛ هیچ پیامکی ارسال نمی‌شود و داده‌های همان اجرای تست در پایان پاک می‌شوند. نتیجهٔ هر اجرا در `reports/otp-load-<runId>.json` ذخیره می‌شود. شناسهٔ نسخهٔ تابع تأیید، مشخصات دستگاه، تعداد واقعی درخواست‌ها، اوج عملیات در انتظار/اجرا، نتیجهٔ ورود و تأخیرها در گزارش آمده است.

دو نوع تست از هم جدا هستند:

- `swapped`: تابع واقعی `verifyPhoneCode` و تراکنش‌های SQL Server را اجرا می‌کند. در هر جفت درخواست، کدهای متفاوت جابه‌جا می‌شوند. تعداد تلاش ثبت‌شده در پایگاه داده نیز بررسی می‌شود تا خطای زیرساخت یا انقضا به‌اشتباه ردشدن OTP محسوب نشود. این تست HTTP و ارسال پیامک را شامل نمی‌شود.
- `http`: فرم واقعی Next.js و Server Action را با کد صحیح برای کاربران مصنوعی مستقل فراخوانی می‌کند. موفقیت فقط پاسخ ۳۰۳ به مقصد ثبت‌نام همراه با کوکی نشست است؛ پاسخ ۲۰۰ حاوی خطای فرم، ورود موفق محسوب نمی‌شود. تعداد ردیف‌های User و Session نیز گزارش می‌شود. تولید و ارسال اولیهٔ OTP خارج از این تست است.

نمونهٔ اجرای آزمون جابه‌جایی ۵۰۰هزار کد با ۶۴ عملیات هم‌زمان:

```powershell
node --import tsx scripts/otp-load-test.ts --mode=swapped --count=500000 --concurrency=64
```

نمونهٔ آزمون HTTP (سرور محلی روی پورت ۳۰۰۰ باید روشن باشد):

```powershell
node --import tsx scripts/otp-load-test.ts --mode=http --count=128 --concurrency=64
```

تعداد کل درخواست‌ها با هم‌زمانی یکی نیست. ۵۰۰هزار بررسی با هم‌زمانی ۶۴، آزمون ۵۰۰هزار کاربر هم‌زمان نیست. `peakInFlight` تعداد فراخوانی‌های در انتظار یا اجرای ابزار است و نشان نمی‌دهد تمام آن‌ها در همان لحظه داخل پایگاه داده در حال اجرا بوده‌اند.

این ابزار با عبور نرخ خطا از ۵٪ یا کاهش حافظهٔ آزاد به کمتر از یک گیگابایت، بعد از اتمام دستهٔ جاری بار را متوقف می‌کند. برای حفاظت از محیط توسعه، هم‌زمانی محلی بیشتر از ۱۰۰۰ را قبول نمی‌کند. آزمون یک‌میلیون کاربر هم‌زمان به اجرای توزیع‌شده روی محیط تست مستقل نیاز دارد؛ ساخت یک‌میلیون Promise یا صف‌کردن یک‌میلیون عملیات به معنی اثبات این ظرفیت نیست.

کد شش‌رقمی شناسهٔ یکتای سراسری نیست. اگر عدد OTP دو درخواست اتفاقاً یکسان باشد، همان عدد در هر دو درخواست معتبر است؛ نسبت‌دادن نشست به شماره از درخواست تأیید سرور تعیین می‌شود. تست بار عمداً «کدهای متفاوت» را جابه‌جا می‌کند. حالت کدهای هم‌عدد جداگانه در تست پایگاه داده پوشش داده شده و تضمین یکتایی جهانی ادعا نمی‌شود.

تست‌های رگرسیون:

```powershell
$env:OTP_DB_TEST='1'
node --import tsx --test src/lib/phone-otp.test.ts
$env:OTP_HTTP_TEST='1'
node --import tsx --test src/lib/phone-auth.http.test.ts
```

این تست‌ها، رد کد جابه‌جا، بی‌اثر بودن شماره و شناسهٔ جعلی داخل فرم، مصرف یک‌باره، سقف پنج تلاش در ۶۴ درخواست هم‌زمان، انقضا هنگام انتظار برای تراکنش و نگاشت درست نشست به شماره را بررسی می‌کنند.
